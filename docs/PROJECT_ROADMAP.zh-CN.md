# MetaI 项目路线与验收标准

## 项目目标与维护约定

MetaI 是面向 2026 前沿规格的全链路大模型研发框架。主线从单机 125M 原型延伸至百万上下文和万亿参数 MoE 集群。CPU 单测、小模型留出实验和中文教程服务于同一套工业研发代码。缺少集群时继续实现可测的通信语义、算子与恢复协议，把硬件相关性能留给对应平台验收。改变目标规模、撤换已有公共入口或切换后端主路线前，应先与项目负责人确认影响和迁移方案。[完整目标与工程记录](INDUSTRIAL.zh-CN.md)

## 当前基线（2026-11-20）

仓库使用 Burn 0.22.1，Apple M2 Pro 已完成 125M 档 Metal 训练更新、保存和重载。Flex CPU 用于可重复的回归测试。执行记录见[CPU 实验](CPU_RUN.zh-CN.md)，复现实验见[中文教程](COURSE.zh-CN.md)。

| 方向 | 已经验证 | 下一个可检验的里程碑 |
| --- | --- | --- |
| 模型、数据、预训练 | GQA、MLA、稀疏注意力、MoE 路由、数据清洗及自训练 BPE；模型／优化器／语料指纹的 epoch 恢复及 logits 等价性 | 对同一授权语料验证 dense 与 top-1/top-2 的质量、路由负载、峰值内存及吞吐。预训练按行分词并建立磁盘块索引；后续按节点持久化分片并衡量端到端 I/O |
| 后训练 | SFT、LoRA、DPO、PPO、GRPO、GSPO、CISPO、AI 裁决、隐状态自适应停止、蒸馏均已完成 tiny 训练与重载 | 扩展多轮对话和适配层；跨种子、留出集对照；独立检验奖励模型评分；补充后训练优化器与采样器恢复 |

以下各阶段是长期目标，按表中的证据继续推进。一轮合成实验只能确认对应的实现路径。

## 分阶段实施

### 0. 建立可复现基线

1. 固定并验证 Rust 工具链、Cargo.lock 和后端组合；整理依赖下载、离线限制与运行方式。
2. 将标准测试与依赖本地临时文件的诊断实验分离，提供仓库内极小测试数据；确保干净环境下测试结果可重现。
3. 检查模型前向、反向、因果遮罩、padding、缓存与非缓存输出；对 MoE 路由和专家梯度设置针对性测试。
4. 制作一条固定随机种子的最小预训练 → 保存 → 加载 → 推理闭环；记录设备、耗时、loss 和结果。小样本 loss 下降只能证明流程可训练，不能证明模型具备实用能力。

**验收**：新环境能按文档运行自动测试及闭环；权重重载前后输出在数值容差内一致；记录已知后端差异。

### 1. 数据与语言模型基础

- 描述文本采集授权、清洗、规范化、去重、质量过滤、训练/验证划分、泄漏检查和数据版本；小型示例展示输入输出并保留来源信息。
- 讲清 tokenizer、特殊 token、数据打包、next-token 目标、因果注意力、损失掩码、优化器、学习率与 checkpoint。
- 验证 dense/MoE 配置，比较激活参数与总参数；记录路由负载与辅助损失是否参与训练。
- 验证断点恢复，包括优化器、随机数状态及数据进度；区分仅加载权重和完整恢复。

**验收**：给定固定小语料可重复构建数据，划分不重叠；小模型稳定训练并可恢复，单元测试覆盖关键边界。

### 2. 后训练与评测

- SFT：约定对话模板、角色边界、截断、只计算回答部分损失及多轮数据规则。
- LoRA：解释低秩矩阵、冻结参数、合并与卸载；比较训练参数量，验证合并前后输出。
- DPO：解释偏好对、固定参考模型及序列对数概率；验证 padding 与 prompt 掩码、参考参数不更新以及数值稳定性。
- PPO、GRPO、CISPO：分别明确策略、采样分布、奖励、优势、损失、KL、裁剪与停止条件；不能仅凭名称认定算法等价。用可计算答案的小环境验证每个算法的关键公式和更新方向。AI 反馈、人工反馈与规则奖励应分别标注来源；DPO 是偏好优化方法，并非必须使用在线强化学习。
- 蒸馏与自适应思考：先实现可测的教师输出或 logits 蒸馏，以及可配置的推理预算实验；分别评估质量、token 消耗及延迟，避免把输出长度等同于推理能力。
- 建立固定数据划分和基线，报告任务指标、样本数、随机种子、失败样本以及硬件资源。

**验收**：每个方法具有数值单测、小模型训练与评测示例；说明参考算法与实际实现的差别。

### 3. 工具使用与 Agentic RL

定义带版本的工具调用数据格式和可验证的轨迹、状态、动作、奖励与终止条件。先用离线、确定性的玩具环境实现多轮训练和评测，覆盖格式错误、工具失败、超时、步数上限及奖励作弊。执行外部工具时由程序负责参数校验和权限控制。区分工具调用 SFT 与基于环境反馈的 RL。

**验收**：可重放样例轨迹；测试成功率、错误恢复和资源上限；无外部付费服务依赖。

### 4. 其他模型方向

- 视觉：图像编码器与视觉语言桥接，从小数据图像分类或图文任务开始；说明预处理和分辨率。
- Omni：分离文本、图像、音频等模态编码和对齐；从可独立运行的多模态最小任务扩展，记录同步、采样率与输入输出限制。
- 扩散语言模型：建立离散扩散的加噪、去噪、训练目标和生成流程；与自回归基线用同一任务比较。
- 线性模型：明确具体为线性注意力、状态空间模型或其他结构，先实现可验证的小型基线，再比较质量、计算量和实际性能。
- 决策模型（Jev 类，见[入门与实验设计](DECISION_MODELS.zh-CN.md)）：面向给定状态与候选项输出有类型的决策及概率，支持分类、布尔判断和有序评分等任务。先以小型骨干加决策头实现固定候选项基线，再研究动态候选项、温度校准和多问题输入。Jev 为闭源服务，不能宣称复现其内部实现；可参考 [TypeSafe 的 Jev 发布说明](https://typesafe.ai/blog/introducing-system-one-models-and-jev)、[Cloudflare 的开放权重 Clef](https://blog.cloudflare.com/clef-decision-models/) 与论文 [Releasing the Inner Jev](https://arxiv.org/abs/2610.17205)（资料查阅：2026-11-20）。第三方实现的代码、模型和数据许可需分别核对。
- 决策模型评测需包含准确率、对数损失、Brier 分数、校准误差、置信度分桶、拒答覆盖率及分布外样本；校准参数只在独立校准集拟合，测试集不可用于调参。类型正确不代表答案正确或概率已校准。

**验收**：每条方向都有明确定义、数据协议、最小训练/推理示例、确定性单测和局限说明。

### 5. 扩展到多卡与集群

先完成多进程初始化、参数和梯度同步、无重叠数据分片、正确的指标归约及断点恢复；再按需要实现专家并行、通信与容错。单机多卡和跨机分别验证，并报告实际设备和结果。没有硬件时可以测试分片和协议逻辑，但不能宣称完成集群性能或扩展性验证。

## 教学资料约定

每个章节依次提供：学习目标与前置知识、最小数学推导、带维度的代码路径、可复制的数据和命令、预期输出及解释、常见错误、动手练习、延伸阅读和实验记录。标注教学简化与论文原版的区别；外部资料附原始论文或官方文档链接及查阅日期。训练命令不能覆盖用户已有 checkpoint，示例应写入明确的独立输出目录。

## 状态标记

- **规划**：只有目标或设计。
- **原型**：存在代码，但关键路径或边界还未完成验证。
- **小模型已验证**：测试和端到端实验可复现，并记录环境与结果。
- **规模化已验证**：在说明的实际数据和硬件上复现，附资源与评测记录。

每个阶段完成时更新状态和证据；不要以代码文件存在、测试通过或单次 loss 下降替代规模化能力和模型质量评估。
