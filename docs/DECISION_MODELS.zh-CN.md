# 决策模型入门：从 Jev 类接口到可验证的本地基线

> 2026-11-20 已在 CPU 上跑通固定标签分类、独立温度校准、评测与重载预测。可执行入口为 `train-decision` 和 `decide`。

## 1. 要解决什么问题

生成模型通常逐 token 生成文字；决策任务经常只需要程序可以直接消费的有限结果。例如：给定一段工单，选择 `退款`、`技术支持` 或 `其他`，并返回各选项的概率。调用方可按业务成本设置阈值，低置信度时转人工。决策模型不限于工单分类，也可用于判断陈述是否成立、对有序等级评分或选择工具。

[TypeSafe AI 的 Jev 发布说明](https://typesafe.ai/blog/introducing-system-one-models-and-jev)介绍了 System One 模型和面向软件使用的结构化决策。Jev 是闭源产品，公开接口不等于公开了内部训练与架构；下面的基线是教学设计，不是 Jev 的内部实现。相关开放研究包括 [Cloudflare Clef](https://blog.cloudflare.com/clef-decision-models/) 和 [Releasing the Inner Jev](https://arxiv.org/abs/2610.17205)。前者发布了开放权重模型，后者研究对现有语言模型进行适配的方案；实际使用前须逐项核对代码、权重和数据许可。

## 2. 教学基线的输入输出

第一阶段先解决**固定标签集**的文本分类，以便验证从数据到训练、预测和评估的完整过程。假设数据为 JSONL，每行一条：

```json
{"text":"订单重复扣款，请帮我退款", "label":"退款"}
{"text":"应用无法登录", "label":"技术支持"}
```

训练集、校准集与测试集按样本或来源分开，避免重复内容跨集合。模型输入为分词后的文本及其有效长度；输出为与标签表同序的 logits。对第 i 个标签，概率为：

```text
p_i = exp(z_i / T) / sum_j exp(z_j / T)
```

其中 `z` 是模型 logits，`T > 0` 是温度；训练或未校准推理时可取 `T = 1`。模型不应在没有校准实验的情况下声称输出可靠置信度。固定标签基线不能直接回答任意新候选项；动态候选项需要把问题与选项编码进输入，再设计相应的逐选项或指针式读出，并单独验证。

## 3. 训练和校准

1. 使用训练集建立或加载 tokenizer，并仅在训练集上更新小型骨干与分类头；交叉熵衡量真实标签的负对数概率。冻结骨干与全量微调可作为对照。
2. 在独立校准集上拟合单个正温度 `T`，最小化负对数似然；保存温度和标签顺序。校准不更新模型权重，不接触测试集。
3. 在保留的测试集上比较校准前后的指标；固定随机种子，并记录数据版本、模型配置、设备和样本数。
4. 通过置信度阈值选择自动处理或转人工，报告覆盖率及已自动处理样本的错误率；阈值按业务损失与校准集确定，而不是在测试集挑选。

## 4. 如何判断结果

- **准确率和混淆矩阵**：模型选对多少、哪类错误最常见；类别不平衡时还需分类别指标。
- **负对数似然**：真实标签被赋予的概率越低，惩罚越大。
- **Brier 分数**：预测概率与 one-hot 真实标签之间的均方误差，需说明采用的多分类归一化约定。
- **校准图和 ECE**：按预测置信度分桶，比较每桶平均置信度与实际正确率。ECE 受分桶方式和样本量影响，应公布分桶规则，不能单独证明可靠性。
- **覆盖率与风险**：改变拒答阈值，观察自动处理比例和其中的错误率；还要测试新领域、标签不匹配和含糊输入。

例如，100 个置信度约 0.8 的独立样本中约 80 个预测正确，才与这一置信度段的校准目标一致；单条 0.8 预测无法证明其正确。类型合法、概率之和为 1 都是格式条件，不是预测正确的保证。

## 5. 在本机重现

```bash
python3 scripts/run_tiny.py --output artifacts/decision-course
./target/debug/metai decide --model-dir artifacts/decision-course/decision --text "red cup"
```

训练、校准和测试分别是 `examples/tiny/decision-{train,cal,test}.jsonl` 的 6、4、4 行。训练标签表由训练集产生，未知标签、空文本和重复文本会报错。输入固定为一条文本，冻结骨干取最后一个有效位置的表示。将头部和温度分别训练后，`schema.json` 保存标签顺序、正温度；`decision.bpk` 保存分类头；`evaluation.json` 保存校准前后的测试指标。具体结果见[本机实验记录](CPU_RUN.zh-CN.md)。

读输出时先检查 `labels[i]` 和 `probabilities[i]` 是否对应。最高概率的候选成为 `label`。例如一次实测将 “red cup” 错选为 blue，置信度约 0.54。在阈值 0.8 下会转人工。所有测试样本被转人工时，`coverage=0`，`selective_risk=null` 表示没有被自动处理的样本可作分母。

温度在独立校准集上从 25 个候选值中选择，以负对数似然最小为准。多类 Brier 采用每条样本对各类的平方误差求和再取样本平均。ECE 采用五个等宽置信度桶，公开每桶的计数、置信度之和及正确数。混淆矩阵按真实类为行、预测类为列，行列均按 schema 中的标签顺序。四条测试样本不足以判断新样本上的概率可靠性。

**扩展练习。** 先增加来自另一来源的测试样本，再增加第三个训练标签。保留一份训练中没有出现过的候选词，分别考察固定标签模型的表达范围，以及逐候选编码后支持动态选项的方案。Jev 的公开资料提供任务和输出协议参考，私有权重、训练数据和 RLCD 配方仍属未知。

## 6. 用同一个名词检查模型读到了哪种信息

只改一个词，再看概率。第一课权重在 `red cup` 和 `blue cup` 上给红色的概率分别为 0.46054 和 0.45912，两个输入都选蓝。独立测试的 16 个新名词上，旧模型没有一个名词能把两种颜色都判对。它对部分名词都选红，对另一些都选蓝，因而总准确率仍有 16/32。

改进实验先把每个训练名词各配两个颜色，再用 `train-decision --pooling mean` 替换默认的 `last`。两种池化都使用同一冻结骨干、同一标签表和线性头。前者均匀平均当前文本的全部有效 token，后者只读取最后位置。池化方式随标签和温度一起写进 `schema.json`，加载旧文件时沿用末位池化。

| 同一独立测试集 | 总正确 | 两种颜色都答对的名词 | NLL | 多类 Brier |
| --- | ---: | ---: | ---: | ---: |
| 第一课权重 | 16/32 | 0/16 | 0.6957 | 0.5026 |
| 成对训练，末位池化 | 23/32 | 7/16 | 0.8840 | 0.4523 |
| 成对训练，均值池化 | 31/32 | 15/16 | 0.1741 | 0.0620 |

成对训练的两行使用相同的 32 条训练数据、8 条校准数据、40 轮训练、批量 4 和学习率 0.015。这个对照可以检验池化的贡献。第一课与第二行同时改变了样本和训练预算，各自能解释多少提升还需要进一步对照。均值模型选到温度搜索下界 0.125，对错误样本 `blue sandal` 给红色的概率仍达 0.99619。若要把概率用于自动处理，还需要更多独立校准数据，以及词序、同义词和分布外输入的评测。[复现命令与效果图](COURSE.zh-CN.md#heldout-comparison) · [逐条预测](experiments/heldout-v1.json)
